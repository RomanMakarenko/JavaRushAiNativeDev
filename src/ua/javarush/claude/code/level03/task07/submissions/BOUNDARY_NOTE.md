# BOUNDARY NOTE — Refund Detail: додавання текстового блоку з поясненням причини ручної перевірки

## Scope
Додати новий текстовий блок із поясненням, чому повернення потрапило на ручну перевірку, на сторінку деталей повернення (refund detail). Дані для тексту вже надходять у наявному payload refund detail — бекенд-контракт не змінюється. Зміна відбувається виключно на боці фронтенду сторінки refund detail.

## Non-goals
- Зміна бекенд-контракту (payload refund detail) — заборонено обмеженням.
- Зміна платіжної інтеграції, авторизації або схеми БД — виключено обговоренням.
- Зміни на інших сторінках (окрім refund detail) — виключено обмеженням «тільки на боці сторінки деталей повернення».

## Affected area
- Сторінка refund detail (фронтенд) — єдиний модуль, де відбувається зміна.
- Candidate files:
  - `refund-detail.tsx` (або аналогічний файл компонента сторінки)
  - `refund-detail.i18n.json` / `refund-detail-messages.json` (файли локалізації для тексту блоку)
  - Якщо текстовий блок виноситься в окремий компонент — відповідний файл компонента та його стилі
