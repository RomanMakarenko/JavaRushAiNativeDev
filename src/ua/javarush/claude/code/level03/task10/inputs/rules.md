# Правила, які накидала команда (потрібно розкласти за місцем дії)

У межах задачі «додати поле `notes` у refund flow» команда зібрала список із 12 правил.
Вони перемішані: частина — загальні для всього проєкту, частина — лише для цієї задачі, частина — це вже
автоматичний контроль, а не текст постановки.

1. У production-коді не повинно бути `console.log`.
2. Ліміт довжини `notes` у цій задачі — рівно 1000 символів.
3. Усі коміти мають проходити pre-commit hook з лінтером.
4. Public refund API response у цій задачі змінювати не можна.
5. Кожен PR проходить CI-перевірку із зеленими тестами перед merge.
6. Не додавати нові runtime-залежності в проєкт.
7. У цій задачі не можна редагувати наявні SQL-міграції.
8. Try not to touch the auth module while editing refunds.
9. Будь-який код форматувати через загальний formatter проєкту.
10. Diff цієї задачі має залишатися маленьким і reviewable.
11. Гілка має бути захищена branch protection rule (без прямого push у main).
12. Усі секрети зберігаються лише в `.env`, не в коді.
