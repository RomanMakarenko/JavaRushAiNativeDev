# Класифікація сценаріїв за робочими одиницями

| # | Сценарій | Термін | Причина |
|---|----------|--------|---------|
| 1 | Пошук файлів | **subagent** | Read-only пошук, результат повертається в поточну розмову, код не змінюється. |
| 2 | Свіжий старт після забрудненого контексту | **separate session** | Потрібен повністю чистий контекст без історії невдалих спроб поточної сесії — почати міркування з нуля. |
| 3 | Довге фонове завдання | **background agent** | Сканування всього репозиторію не потребує постійного діалогу; результат з'явиться пізніше. |
| 4 | Ризиковані паралельні правки | **worktree-backed session** | Експериментальна реалізація не має змішуватися з основним робочим деревом і поточною гілкою. |
| 5 | Координація кількох виконавців | **agent team** | Велику фічу розбито на ролі (планування → реалізація → тестування) зі спільною координацією. |
| 6 | Вузьке спеціалізоване рев'ю | **subagent** | Read-only виконавець перевіряє локальний diff за чек-листом і повертає висновки в поточний процес. |
