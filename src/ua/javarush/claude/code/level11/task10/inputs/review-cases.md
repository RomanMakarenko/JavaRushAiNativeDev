# Review cases: багфікс порядку сповіщень

Контекст: у notifications-сервісі сповіщення показувалися у зворотному порядку.
Готується локальний багфікс. Нижче чотири ситуації навколо цієї зміни.

## Case 1 — Готовий diff
Розробник зібрав невеликий diff: виправлено сортування в `NotificationService.list()`.
Diff локальний, перед будь-яким merge потрібно його прочитати й оцінити коректність зміни.

## Case 2 — Тест, що падає
Після правки `./gradlew test` показує червоний тест
`NotificationServiceTest.shouldOrderNewestFirst`. Потрібно зрозуміти, чи справді
поведінку перевіряють коректно, і відтворити падіння в ізоляції.

## Case 3 — Незрозумілий stack trace
У логах з'явився `NullPointerException` з незрозумілим stack trace в районі
`NotificationMapper`. Зв'язок із поточним diff неочевидний, потрібно докопатися до root cause.

## Case 4 — Застарілий README
У `docs/notifications.md` досі написано, що сповіщення показуються
"oldest first". Після багфікса опис став неправильним, і його потрібно привести
у відповідність із фактичною поведінкою.
