# Класифікація ризику змін

Документ описує, як команда оцінює ризик зміни перед merge.

## Low

Локальні правки без впливу на зовнішню поведінку: рефакторинг приватних методів,
тести, документація. Достатньо одного review.

## Medium

Зміни в бізнес-логіці refund flow, нові ендпоінти, правки конфігурації.
Потребують review і прогону quality gates.

## High

Зміни схеми БД (`db/migration/**`), робота із секретами (`.env`, `secrets/`),
будь-які дії з деплоєм (`deploy`) і операції з protected branch.
Потребують explicit approval відповідального інженера.
