# Target roles

## Level

Junior / early-career backend engineer. Фокус — на ролях, де можна показати самостійну реалізацію API, бізнес-логіки, тестів і CI без перебільшення production-досвіду.

## Primary roles

- **Junior Java Backend Engineer** — традиційна інженерна роль для розробки backend-сервісів на Java/Spring Boot, реалізації бізнес-правил, REST API та тестів.
- **Junior Backend Engineer / API Developer** — роль із фокусом на API-контрактах, integration- і regression-тестах, quality gates та підтримуваності сервісу.

## Stretch roles

- **[Stretch] Backend Engineer у команді, що активно використовує AI-assisted development** — наступний крок після закріплення базової backend-ролі; AI є посиленням інженерного процесу, а не окремою спеціалізацією.
- **[Stretch] Software Engineer з фокусом на developer productivity** — варіант для ролей, де backend-досвід можна поєднати з покращенням investigation, тестування, documentation і CI workflow.

## Avoid for now

- AI Engineer, ML Engineer або інші AI-only ролі, де основним доказом очікуються production ML-системи, моделі чи data pipelines.
- Senior/Staff/Lead позиції та engineering management: поточні докази підтверджують самостійну роботу над одним навчальним сервісом, але не production ownership, leadership або people management.
- Production-heavy ролі з вимогами до реального трафіку, on-call та експлуатації: у capstone не було production deployment і production traffic.

## AI advantage

Claude Code посилює традиційний backend workflow: допомагає швидше проводити investigation і готувати чорнові рішення, після чого кожен diff перевіряється вручну, проходить self-review і CI quality gate. Це підвищує швидкість і якість роботи з кодом, тестами, regression-fix та документацією, але не замінює базові навички Java backend engineering і особисту відповідальність за рішення та merge.
