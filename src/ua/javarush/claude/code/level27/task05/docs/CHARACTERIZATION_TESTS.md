# Characterization tests — mrr-engine

Цей baseline фіксує спостережувану поведінку legacy-модуля `mrr-engine`
до початку декомпозиції. Будь-яке seam-extraction має залишити ці перевірки
зеленими.

## Покриті сценарії

| Поведінка | Де перевіряється | Стан |
|-----------|------------------|------|
| Місячний MRR для наявного плану | `MrrFacadeTest` | покрито |
| Сумарний MRR зі знижкою | `MrrCalculatorTest` | покрито |
| Refund за невикористані дні | немає тесту | НЕ покрито |

## Відомі особливості

- `monthlyMrr` повертає `0`, якщо план не знайдено (не кидає виняток).
- `refundForCancellation` ділить ціну на фіксовані 30 днів і округлює HALF_UP.
- `totalMonthlyMrr` пише audit-подію навіть за нульового результату.

## Спостереження щодо coupling (чернетка)

- `MrrFacade` напряму тримає `JdbcTemplate` і `AuditSink`.
- refund-логіка змішана з розрахунком і побічним audit-ефектом.
- чиста формула MRR захована всередині `MrrCalculator.totalMonthlyMrr`.
