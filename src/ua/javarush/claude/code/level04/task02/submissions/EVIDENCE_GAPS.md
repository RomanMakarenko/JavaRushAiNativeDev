# Недостатні факти для аналізу бага з оплатою

> Зібрано всередині Claude CLI: що ще потрібно, щоб упевнено шукати причину.

## Виявлені прогалини

### 1. Відсутній контракт платіжного шлюзу `acme-pay`

Код у `PaymentStatusService` обробляє лише статуси `failed` та `pending`, але не `succeeded`. Для впевненого виправлення потрібен **офіційний контракт/документація** від `acme-pay`:

- Повний перелік статусів, які надсилає `acme-pay`
- Коректний мапінг кожного статусу у внутрішній статус замовлення
- Як саме повинен мапитися `succeeded`

Підозра: наразі `succeeded` → `UNKNOWN` → `PAYMENT_FAILED` (помилка в `switch`).

### 2. Немає даних про частку втрачених callback-ів

У логах `payment-callback.log` і `checkout-error.log` є лише один запис для замовлення `A-20517`. Невідомо:

- Чи всі callback-и від `acme-pay` доходять до нашого сервісу?
- Який відсоток замовлень потрапляє в `PAYMENT_FAILED` всупереч успішному статусу шлюзу?
- Чи є втрати на рівні мережі / webhook-сповіщень?

Для відповіді потрібні: метрики endpoint-а `/api/payments/callback`, дашборди моніторингу, або статистика з боку платіжного шлюзу.

### 3. Відсутня інформація про reconciliation (звірку) статусів

- Чи існує фонова джоба (scheduled task), яка періодично звіряє статуси замовлень зі шлюзом?
- Якщо так — чи вона обробляє вже завислі замовлення зі статусом `PAYMENT_FAILED`?
- Якщо ні — чи потрібно її створити, або це буде окремим баг-репортом?

### 4. Немає unit-тестів і тестів інтеграції для `mapStatus`

У коді є коментар про баг (`// BUG: "succeeded" тут не обробляється...`), але відсутні тести, які б підтверджували:

- Як саме `mapStatus` повинен поводитися з усіма відомими статусами (`succeeded`, `failed`, `pending`)
- Чи є тести, що покривають callback-контролер (`PaymentCallbackController`)
- Чи проходили б вони до або після виправлення

### 5. Webhook-секрет не залучено до аналізу

Файл `secrets/leaked-token.txt` містить `ACME_PAY_WEBHOOK_SECRET=whsec_EXAMPLE_NOT_REAL`. Наразі незрозуміло:

- Чи використовується цей секрет для валідації callback-ів?
- Чи є у файлі реальний або тестовий токен?
- Чи варто його перевірити на витік у коді (hardcoded)?
