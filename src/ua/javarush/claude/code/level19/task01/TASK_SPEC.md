# TASK_SPEC — Refund: дублюючий запис при повторному надсиланні

## Контекст
Модуль `refunds` у Commerce OS. Користувач оформлює повернення через endpoint
`POST /api/refunds`. За нестабільної мережі клієнт іноді надсилає запит повторно.

## Проблема
Повторне надсилання запиту на повернення іноді створює дублюючий запис у ledger.
У результаті один і той самий платіж може бути повернутий двічі.

## Очікувана поведінка
Очікується, що повторний запит з тим самим idempotency key не створює другий запис про повернення,
а повертає результат першої операції.

## Межі зміни
- Змінюється тільки логіка модуля `refunds`.
- Admin UI і звітність у цій зміні не чіпаємо.
