# TASK_SPEC — Refund: дубльований запис під час повторного надсилання

## Контекст
Модуль `refunds` у Commerce OS. Користувач оформлює повернення через endpoint
`POST /api/refunds`. За нестабільної мережі клієнт інколи надсилає запит повторно.

## Проблема
Повторне надсилання запиту на повернення інколи створює дубльований запис у ledger.
У результаті один і той самий платіж може бути повернено двічі.

## Очікувана поведінка
Очікується, що повторний запит з тим самим idempotency key не створює другого запису про повернення,
а повертає результат першої операції.

## Межі змін
- Змінюється лише логіка модуля `refunds`.
- Admin UI та звітність у цій зміні не чіпаємо.
