# Handoff package

## Result

Готовий до review результат для прототипу Personal CFO: CSV-виписка проходить
потік імпорту, автоматичної категоризації та побудови місячного звіту.

- [README](README.md) — короткий опис продукту, quick start і основний потік.
- [SPEC](SPEC.md) — problem statement, scope, non-goals та критерії перевірки.
- [DEMO](DEMO.md) — покроковий сценарій демонстрації й запасний варіант для live demo.

Цей пакет описує поточний стан прототипу; він не є заявою про готовність до
production-використання.

## Process

Рішення перевірялося інкрементально: окремо для імпорту CSV та окремо для
місячного звіту. Зафіксовані прийняті й відхилені зміни, результати тестів та
smoke-перевірок наведені в [EVIDENCE](EVIDENCE.md).

### Verification commands

```bash
# Повний набір unit і regression тестів
pytest -q

# Перевірка імпорту CSV
pytest -q tests/test_import.py

# Перевірка місячного звіту
pytest -q tests/test_report.py

# Smoke flow із прикладом виписки
docker compose up -d
python -m app.cli import data/sample.csv
python -m app.cli report --month 2026-04
```

Очікуваний smoke-результат: `data/sample.csv` створює звіт за квітень із
підсумками за категоріями та балансом. Команди запускаються в корені проєкту,
а не в цій директорії з документацією.

## Honesty

- Це обмежений прототип, а не повноцінна бухгалтерська система.
- Підтримується одна CSV-виписка за раз; банківські API не підключені.
- Багатовалютність не реалізована: приклади використовують USD.
- У demo використовується один тестовий користувач; signup, multi-user
  авторизація та пов’язані сценарії не входять у scope.
- Імпорт перевірено для файлів до 10MB; файли більшого розміру ще не тестувалися.
- Повний перелік відомих обмежень див. у [README — Відомі обмеження](README.md#відомі-обмеження),
  а межі функціональності — у [SPEC — Non-goals](SPEC.md#non-goals).

## Questions for review

1. Чи достатньо поточного формату місячного звіту для першого користувацького
   сценарію, чи потрібно додати деталізацію окремих транзакцій?
2. Які правила категоризації потрібно затвердити перед розширенням набору
   прикладів і regression-тестів?
3. Чи має наступна ітерація спочатку збільшити покриття великих/некоректних CSV,
   чи спершу підготувати інтеграційний контракт для банківського API?
4. Які вимоги до конфіденційності та маскування даних мають бути визначені до
   роботи з не-тестовими виписками?

## Next steps

3. Додати перевірку порожньої виписки, дубльованих транзакцій і відсутніх

4. Після погодження формату звіту підготувати ізольований контракт для майбутньої
   інтеграції з банківським API.
