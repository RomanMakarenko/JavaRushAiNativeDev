# Sprint backlog — personal-cfo-web

> **Статус spec:** FROZEN. Цей backlog описує лише execution sprint у межах `SPEC.md`; нові можливості не додаються без явного розморожування spec.

## Core flow

**Демонстраційний шлях:** користувач завантажує CSV з транзакціями → застосунок парсить рядки та розкладає суми за категоріями → `buildMonthlyReport` будує місячний звіт із сумарним доходом, сумарною витратою та розбивкою за категоріями → звіт показується на сторінці звіту.

**Критерій готовності flow:** шлях проходиться від завантаження CSV до читабельного місячного звіту менш ніж за хвилину на валідному вхідному файлі.

## Must-have

1. **Завантаження CSV з транзакціями**
   - Дати користувачу один зрозумілий шлях вибору CSV-файлу.
   - Передати завантажені дані до обробки без додавання зовнішніх інтеграцій.

2. **Парсинг рядків CSV**
   - Прочитати транзакції з файлу та підготувати їх до побудови звіту.
   - Некоректний вхід не повинен непомітно перетворюватися на правильний звіт.

3. **Побудова місячного звіту через `buildMonthlyReport`**
   - Обчислити сумарний дохід і сумарну витрату.
   - Сформувати розбивку сум за категоріями.

4. **Перегляд звіту на сторінці звіту**
   - Показати користувачу дохід, витрату та категорійну розбивку в читабельному вигляді.
   - Зберегти послідовність core flow: після обробки CSV користувач бачить саме сформований місячний звіт.

## Nice-to-have

Ці пункти не розширюють frozen scope, а покращують надійність і зрозумілість уже визначеного flow:

- Додати перевірку формату CSV та зрозуміле повідомлення про помилку для порожнього або пошкодженого файлу.
- Покрити парсинг і `buildMonthlyReport` тестами на типовому валідному CSV та базових крайніх випадках.
- Додати короткі підписи/форматування сум на сторінці звіту, щоб дохід, витрата й категорії швидко читалися.

## Later

Ідеї з `notes/brainstorm.md`, припарковані за межами поточного frozen sprint. Для реалізації кожної потрібне окреме рішення щодо розморожування або зміни spec:

- Авто-категоризація за ключовими словами в описі транзакції.
- PDF export готового звіту для відправлення бухгалтеру.
- Multi-currency: перерахунок витрат у базову валюту.
- OAuth-вхід через Google для збереження історії звітів.
- Графіки (pie chart) за категоріями.
- Порівняння двох місяців між собою.
- Push-нагадування раз на місяць «завантаж виписку».
- Інтеграція з банківським API замість ручного завантаження CSV.

## Open risks

- **Варіативність CSV:** різний роздільник, кодування, порядок колонок або формат дат може зламати парсинг і дати неправильні підсумки.
- **Знак і тип суми:** неоднозначне трактування додатних/від'ємних значень може переплутати дохід із витратою.
- **Неповні рядки:** пошкоджені або частково заповнені транзакції можуть вплинути на категорійні підсумки, якщо їх не валідувати.
- **Продуктивність у браузері:** великий CSV може збільшити час від завантаження до звіту й поставити під загрозу success metric — менше хвилини.

## Scope guardrails

- У поточному sprint залишаються лише завантаження CSV, побудова місячного звіту та його перегляд на сторінці.
- PDF export, OAuth, multi-currency analytics і банківські API є non-goals поточного sprint.
- Product code у межах цього артефакту не змінюється.
