# SCOPE MATRIX — Матриця відповідності сценаріїв типам скоупу

| Сценарій | Тип скоупу | Пояснення |
|:---|:---|:---|
| **1** — Особистий плагін із гарячими клавішами та нотатками, доступний у всіх репозиторіях на машині розробника, без впливу на команду | **user** | Плагін має бути доступний *одному розробнику* в *усіх його проєктах*, але не нав'язуватися нікому іншому. Скоуп `user` (`~/.config/JetBrains/…`) — єдиний, який діє глобально на машині користувача, поза межами окремого репозиторію. |
| **2** — Експериментальний плагін в одному локальному репозиторії; розробник не впевнений у стабільності, не хоче нав'язувати команді | **local** | Розробник тимчасово пробує плагін *тільки в локальній копії* конкретного проєкту без можливості потрапити до VCS. Скоуп `local` — це `.idea/` поза version control (не додається до VCS/не потрапляє іншим). |
| **3** — Спільний code-review workflow, який має автоматично підключатися в усіх учасників одного репозиторію; поза ним не потрібен | **project** | Командний інструмент у межах *одного репозиторію*, що має поширюватися на всіх учасників. Скоуп `project` — `.idea/` через VCS — автоматично синхронізується з усіма, хто клонує проєкт. |
| **4** — Набір обов'язкових плагінів, централізовано розгорнутих адміністрацією для всієї організації; розробник не може вимкнути | **managed** | Політика діє на *всю організацію*, є *обов'язковою* для всіх співробітників. Скоуп `managed` (централізований config з read-only режимом) адмініструється адміністрацією та не може бути змінений або вимкнений локально. |
