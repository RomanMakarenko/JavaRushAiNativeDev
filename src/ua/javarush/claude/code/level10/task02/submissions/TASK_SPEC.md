# Task spec: повернення грошей зависає у статусі "в обробці"

## Goal
Запобігти створенню дублюючих запитів на повернення при повторному натисканні кнопки та гарантувати, що статус повернення завжди досягає фінального стану.

## Scope
- Додати захист від повторного натискання кнопки "Повернути гроші" (debounce / disable після першого кліку).
- Впровадити ідемпотентність на рівні бекенду: другий запит з тим самим payment ID не створює нову операцію, а повертає статус вже існуючої.
- Додати логування повторних спроб для подальшого моніторингу.
- Виправити механізм оновлення статусу повернення, щоб він гарантовано доходив до фінального стану ("повернено" або "помилка"), а не залишався "в обробці" назавжди.

## Acceptance
- Повторне натискання кнопки "Повернути гроші" під час виконання першого запиту не створює другий запит на бекенд.
- Два одночасних запити з однаковим payment ID не створюють дублюючих операцій — другий запит повертає статус першого.
- Статус повернення завжди завершується одним із фінальних значень ("повернено" або "помилка") протягом визначеного таймауту.
- У логах фіксуються всі повторні спроби виконати повернення для того самого платежу.
