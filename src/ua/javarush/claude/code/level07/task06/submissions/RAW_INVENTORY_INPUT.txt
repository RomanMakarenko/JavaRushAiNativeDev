7. КЛЮЧОВІ ЗНАХІДКИ
────────────────────────────────────────────────────────────────────────────────

  * Завдання — гібридний full-stack проєкт (backend + frontend в одному
    репозиторії, але з окремими build-системами).
  * Фронтенд — поки що тільки package.json без жодного React-компонента
    або Vite-конфігурації.
  * Spring Boot застосунок без src/main/resources/ — при запуску буде
    використано дефолтні налаштування, що означає:
    - Сервер стартує на порту 8080
    - Datasource не сконфігуровано — application.properties обов'язковий
      перед підключенням до БД
    - Без нього bootRun впаде з помилкою "Failed to configure a DataSource"
  * Єдиний тест (StoreApplicationTest) перевіряє лише підняття контексту.
  * lib/game-engine.jar — зовнішня залежність, але не підключена в build.gradle.kts.
  * Архітектура "багато окремих завдань в одному src/" — типова для
    навчального курсу Javarush.

8. POTENTIAL HIGH-RISK AREAS
────────────────────────────────────────────────────────────────────────────────

  [H1]  Відсутній application.properties → жодна JPA-сутність або
        DataSource не налаштовані; перший же запуск із H2 за замовчуванням
        (або без нього) упаде з помилкою конфігурації БД.
  [H2]  Відсутній Gradle wrapper → неможливо гарантувати версію Gradle
        при CI-збірці; збірка залежить від середовища розробника.
  [H3]  Фронтенд без жодного вихідного файлу (тільки package.json) —
        `npm run dev` запустить Vite, але сторінка буде порожньою /
        помилка 404 на index.html.
  [H4]  game-engine.jar у lib/ не підключено в build.gradle.kts —
        якщо ця бібліотека потрібна, застосунок скомпілюється, але
        runtime-виклики впадуть із ClassNotFoundException.
  [H5]  Docker Compose має пароль у plaintext (store_local_dev_password)
        та жорстко закодований порт 5432 — небезпечно для production.
