# LOOP_MAP — карта етапів issue-to-PR

Тикет: **BUG: refund не повертає залишок на складі** (`SKU-1024`).
`inputs/` — read-only; усі проміжні артефакти складаємо в `submissions/`.

| Етап | Вихідний артефакт | Дії Claude | Рішення human-only |
|---|---|---|---|
| **Issue** | `inputs/issue.md` (вхід) | Читає issue, фіксує суть бага, кроки відтворення, очікувану/фактичну поведінку. | Написати та затвердити issue до старту циклу. |
| **Issue Intake Note** | `submissions/INTAKE.md` | Сумаризує суть, scope і вплив; формулює критерії приймання; ставить уточнюючі питання. | Підтвердити scope; відповісти на питання. |
| **Investigation Note** | `submissions/INVESTIGATION.md` | Трейсить `OrderController.refund()` і сервіс складу; відтворює сценарій; знаходить корінь (списання без повернення); оцінює ризики. | Затвердити діагноз і напрямок фіксу. |
| **Implementation Plan** | `submissions/PLAN.md` | Пропонує фікс, набір PR-слайсів, план верифікації, перелік ризиків. | **Approve плану** (гейт). |
| **PR slices** | `submissions/PR_SLICES.md` | Нарізає зміни на оглядабельні слайси (service → controller → tests), вказує порядок і залежності. | Погодити межі та розмір слайсів. |
| **Implementation** | Гілка + коміти + PR (git) | Пише код, править/додає тести, комітить, відкриває PR, реагує на фідбек. | Рев'ю PR; **merge** (гейт). |
| **Verification** | `submissions/VERIFICATION.md` + тест-ран | Запускає тести/скрипти, відтворює сценарій issue (refund → залишок відновлено), фіксує вердикт. | Підтвердити відповідність критеріям приймання. |
| **Review** | `submissions/REVIEW.md` (рев'ю дифу) | Аналізує диф на регресії/недообробку, формує зауваження; за потреби вертає в Investigation/Implementation. | **Прийняття ризиків**; фінальне рішення про merge. |

## Гейти human-only (не делегуються Claude)

- **Approve плану** — затвердити `PLAN.md` перед реалізацією.
- **Merge** — злиття PR лише за рішенням людини.
- **Прийняття ризиків** — будь-який залишковий ризик, що його Claude позначив у Review/Plan, приймає людина.
