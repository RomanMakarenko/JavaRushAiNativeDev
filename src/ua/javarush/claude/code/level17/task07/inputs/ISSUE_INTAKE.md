# Issue Intake Note

## Problem
В API замовлень ендпоінт `GET /api/orders` іноді повертає замовлення у неправильному порядку: замість сортування за датою створення (нові зверху) клієнти періодично отримують список, відсортований у довільному порядку. Через це мобільний застосунок показує старі замовлення першими.

## Impact
- Зачеплені всі клієнти, що відкривають список замовлень.
- Зростає кількість звернень до підтримки: "не бачу своє свіже замовлення".
- Severity: high, бо ламається основний сценарій перегляду замовлень.

## Reproduction
- Створити два замовлення з різницею в кілька секунд.
- Запросити `GET /api/orders`.
- Спостерігати, що нове замовлення опиняється не на першій позиції.

## Open questions
- Чи має сортування застосовуватися на рівні запиту до БД чи в сервісному шарі?
- Чи потрібно зберігати стабільний порядок при однаковому часі створення (tie-breaker за id)?
- Чи є клієнти, які покладаються на поточну (зламану) поведінку?

## Acceptance
- `GET /api/orders` повертає замовлення строго за спаданням дати створення.
- Поведінка покрита тестом і стабільна при рівних датах.
