# Issue Intake Note

## Problem
У розділі сповіщень ендпоінт `GET /api/notifications` показує сповіщення у випадковому порядку. Користувачі очікують, що непрочитані та більш свіжі сповіщення будуть зверху, а зараз старе прочитане сповіщення може опинитися вище за нове непрочитане.

## Impact
- Зачеплено всіх користувачів, які відкривають центр сповіщень.
- Користувачі пропускають важливі нові сповіщення.
- Severity: medium-high, ламається ключовий UX-сценарій.

## Reproduction
- Мати кілька сповіщень із різними датами та статусом read/unread.
- Запросити `GET /api/notifications`.
- Спостерігати, що порядок не відповідає "спочатку свіжі непрочитані".

## Open questions
- Який пріоритет важливіший: статус unread чи дата створення?
- Чи потрібен стабільний tie-breaker за рівних дат?

## Acceptance
- `GET /api/notifications` сортує сповіщення за спаданням дати створення.
- Порядок стабільний і покритий тестом.
