# Нотатка про revert

## Що сталося

Гілка `refund-banner-fix` використовується для виправлення порту сервісу `commerce-refund`. Після першого виправлення (порт `9090` → `8080`) було зроблено навмисний "поганий" коміт, який знову змінив порт на `9090`, щоб імітувати помилкове внесення змін іншим розробником.

## Який коміт скасовано

Скасовано коміт `c65eb4b` з повідомленням *"second fix"* — він змінив `server.port=8080` на `server.port=9090`, що ламало smoke test `PortConfigTest`.

## Чому revert, а не reset

`git reset` переписує історію гілки — видаляє коміт із логу. Це безпечно лише для локальних змін, які ще ніхто не бачив. Якщо гілка вже опублікована (або її хтось склонував), `reset` створить розбіжність: в інших клонів залишиться старий коміт, і при `git push --force` ці клони ламаються.

`git revert` натомість створює *новий* коміт, який скасовує зміни старого, не чіпаючи історію. Усі, хто вже мають гілку, можуть просто зробити `git pull` і отримати узгоджений стан — без конфліктів і примусового перезапису.

## Підсумок

- **`git reset`** — змінює історію ✅, **небезпечно** для публічної гілки ❌
- **`git revert`** — не змінює історію ❌, **безпечно** для публічної гілки ✅
