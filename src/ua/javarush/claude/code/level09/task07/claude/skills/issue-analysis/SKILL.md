# issue-analysis

Проаналізуй вхідний issue і перетвори його на інженерну постановку задачі.

## Expected output

Markdown-документ `TASK_SPEC.md` із секціями:

| Секція | Що містить |
|---|---|
| **Мета** | Який результат вважається успішним — одним реченням |
| **Контекст** | Передумови, технічні обмеження, пов'язані задачі |
| **Обсяг (Scope)** | Що входить у задачу / що свідомо лишається за межами |
| **Критерії готовності (DoD)** | Перевірювані умови, за яких задача вважається виконаною |
| **Запитання** | Що необхідно уточнити в авторів issue перед стартом |

## Constraints

- Працюй лише з текстом наданого issue — нічого не домислюй.
- Якщо в тексті є суперечності або прогалини — винеси їх у секцію «Запитання», не заповнюй порожнечу здогадками.
- Не пропонуй конкретний код і не починай редагувати файли.
- Пиши коротко, по суті, без води.
