# Decision Map — Workflow-болі → Механізми розширення

## Таблиця рішень

| # | Проблема | Механізм | Чому саме він |
|---|----------|----------|---------------|
| 1 | Щоразу пишемо один довгий prompt для розбору issue | **Skill** | Повторюваний сценарій-команда, яку хочуть викликати `/parse-issue`. Skill — єдиний спосіб зробити кастомну слеш-команду з prompt-ом. |
| 2 | Межа «без broad refactor біля refund logic» тільки для `payments/**` | **Rule** | Обмеження скоуповане на одну директорію, не на весь репозиторій. Правило в `.claude/rules/payments.md` застосовується автоматично тільки для файлів у цьому шляху. |
| 3 | Регулярно підтягувати дані з Jira (статус, коментарі) | **MCP** | Зовнішній сервіс з API. MCP-сервер дає інструменти, а не інструкції — Claude може викликати `get_ticket`, `get_comments` як функції. |
| 4 | Автоматичний запуск форматера після кожного редагування | **Hook** | Подієва автоматизація: «після запису файла → запусти форматер». Claude Code hooks (`post-*`) тригеряться на події, prompt-и й інструкції не можуть реагувати на події. |
| 5 | Важке investigation засмічує основний контекст сесії | **Subagent** | Потрібна ізоляція: окремий контекст, багато кроків, чистий звіт наприкінці, без забруднення основної сесії. Subagent саме для цього. |
| 6 | Загальна інструкція: план до правок, чистий working tree | **CLAUDE.md** | Проєктні wide-scope вказівки, які діють на всі файли та всі сесії. CLAUDE.md — єдине місце для таких «конституційних» правил. |
| 7 | Одноразове перейменування змінної в одному файлі | **Prompt** | Не повторюється — не потребує жодного механізму. Просто попросити Claude в prompt-і. Механізм має сенс тільки для повторюваних задач. |
| 8 | Роздати команді єдиний набір: правила + skills + налаштування | **Plugin** | Plugin — єдиний формат, який пакує всі типи розширень (rules, skills, settings, hooks) в один встановлюваний пакет. |

## Схема покриття

```
Prompt ───── #7  (одноразове, не потребує інфраструктури)
CLAUDE.md ── #6  (загальнопроєктні інструкції)
Rule ─────── #2  (директорно-скоуповані обмеження)
Skill ────── #1  (повторюваний сценарій зі слеш-командою)
Subagent ─── #5  (ізольоване дослідження зі звітом)
MCP ──────── #3  (інтеграція з зовнішнім API — Jira)
Hook ─────── #4  (реакція на подію — post-edit форматування)
Plugin ───── #8  (пакування та дистрибуція всього набору команді)
```
