# issue-analysis

Проаналізуй вхідний issue і перетвори його на інженерну постановку задачі.

Кроки:
1. Прочитай текст issue повністю.
2. Виділи мету: який результат вважається успішним.
3. Опиши, що входить у задачу і що свідомо залишається за її межами.
4. Сформулюй перевірювані критерії готовності.
5. Не пропонуй конкретний код і не починай редагувати файли.

Пиши коротко, по суті, без води.

## Очікуваний результат

Skill створює `TASK_SPEC.md` з розділами `Goal`, `Scope`, `Constraints` і `Verification`.
Це єдиний артефакт на виході.

## Обмеження

- Skill не починає implementation: не пише і не править production code.
- В артефакті фіксуються лише межі задачі та критерії, без diff і патчів.
