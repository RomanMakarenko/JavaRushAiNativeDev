# Issue BILL-218: повторне списання при ретраї оплати

## Що відбувається

Користувачі скаржаться, що під час оплати рахунку іноді списується подвійна сума.
Відтворюється, коли клієнт натискає «Оплатити» повторно, не дочекавшись відповіді,
або коли мобільний застосунок сам робить retry через таймаут.

## Де дивилися

Підозра на `BillingService.charge(...)`: на кожен виклик створюється новий платіж
у зовнішнього провайдера, без перевірки, чи не було вже успішного списання за цим рахунком.

## Обмеження від команди

- Не можна ламати зворотну сумісність HTTP-ендпоінта `POST /api/billing/charge`.
- Зміни мають потрапити в поточний релізний цикл, без переписування платіжного шару.
- Поведінку повернень (`refund`) у цій задачі не чіпаємо.

## Як зрозуміємо, що виправили

Повторний запит на оплату одного й того самого рахунку в межах вікна ретраю
не створює другий платіж і не списує гроші двічі.
