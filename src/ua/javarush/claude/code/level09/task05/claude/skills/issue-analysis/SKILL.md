# Issue Analysis Skill

## Purpose
Аналіз проблеми (issue/bug) у коді: зрозуміти першопричину, оцінити вплив, запропонувати план виправлення. Допомагає структурувати розслідування дефекту від початкового опису до готового до імплементації завдання.

## When to use
- Надходить баг-репорт або опис проблеми від QA / користувача
- Потрібно розібратися, чому код не працює очікуваним чином
- Перед початком роботи над виправленням складної помилки
- Для створення чіткого ТЗ на виправлення, яке можна передати іншому розробнику

## Inputs
- Опис проблеми (текст, скріншот, лог помилки)
- Посилання на файли/рядки коду, де виникає проблема (за наявності)
- Інформація про середовище (ОС, версія, браузер тощо)
- Кроки для відтворення (якщо відомі)

## Expected output
- **TASK_SPEC.md** — заповнений шаблон технічного завдання на виправлення, який містить:
  - Діагноз (першопричина)
  - Запропоноване рішення
  - План імплементації (файли, зміни)
  - Критерії приймання
- (Опціонально) Посилання на створену GitHub Issue

## Constraints
- Не виходити за межі поточної робочої директорії проєкту
- Skill **не починає імплементацію** — лише аналіз і створення TASK_SPEC.md
- Дотримуватись шаблону `TASK_SPEC.template.md` для вихідного документа
- Якщо першопричину не вдалося встановити однозначно — чесно зазначити ступінь невизначеності
