# Робочий простір для тріажу issue

Невеликий репозиторій, де команда накопичує prompt-сценарії для розбору вхідних issue.

## Що тут є

- `prompts/` — markdown-файли з prompt-сценаріями для різних завдань.
- `submissions/` — робочі артефакти, які ми готуємо в ході аналізу.

## Очікуваний артефакт розбору issue

Для кожного вхідного bug report ми хочемо отримувати один і той самий документ —
короткий `TASK_SPEC.md` з розділами Goal, Scope, Acceptance criteria і Verification.
Реалізацію на цьому кроці не починаємо, лише специфікація.
