# Prompt: розбір вхідного issue (варіант 1)

Використовується, коли в трекер падає новий bug report і його потрібно перетворити
на коротку інженерну специфікацію для наступного кроку.

## Вхід
- Текст issue з трекера.
- Посилання на зачеплені файли, якщо вони вже відомі.

## Що зробити
1. Прочитати issue і виділити поточну та очікувану поведінку.
2. Визначити зачеплену область коду.
3. Сформулювати критерії приймання.
4. Описати, як перевірити результат локально.

## Очікуваний вихід
Короткий markdown-документ TASK_SPEC з розділами Goal, Scope,
Acceptance criteria і Verification. Реалізацію не починати.
