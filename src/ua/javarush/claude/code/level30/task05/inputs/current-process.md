# Поточний процес обробки тикетів

1. Тикет падає в загальну чергу без пріоритизації.
2. Оператор першої лінії відкриває тикет і визначає тип запиту вручну.
3. Для повернень оператор шукає схожий попередній тикет і копіює шаблон відповіді.
4. Якщо сума повернення велика, потрібне ручне погодження у старшого оператора.
5. Відповідь надсилається клієнту, тикет закривається.

Вузькі місця:
- Ручний пошук шаблону забирає час на кожному тикеті.
- Немає чіткого порогу, після якого повернення йде на ручне підтвердження.
- Історія по клієнту розкидана по кількох системах.
