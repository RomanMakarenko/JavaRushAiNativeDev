# MVP_SPEC — AI Support Agent (фрагмент demo-релізу)

> Це design-рішення для demo-slice. На цьому етапі код у `app/` і `tests/` не
> редагується: перелічені файли є affected area для наступної реалізації.

## Ціннісна пропозиція

Проєкт призначений для оператора служби підтримки, який щодня переглядає
клієнтські звернення і має швидко визначати, до якої теми їх віднести. Його
проблема — ручний перегляд забирає час, а помилкова класифікація може передати
фінансово чутливе звернення не тій людині.

У core scenario оператор подає текст звернення про повернення, отримує його тему
та використовує результат як підказку для подальшої ручної обробки. На demo
показується один відтворюваний приклад: звернення «хочу оформити повернення»
визначається як `refund`; жодне повернення коштів при цьому не виконується.

## Контекст проєктного рішення

Поточний вихідний стан не проходить фільтр надійності demo: конфігурація за
замовчуванням обирає зовнішній платний `topclass-api`, а без
`CLASSIFIER_API_TOKEN` не запускається (`app/settings.py`). Навіть із
конфігурацією клієнт завжди намагається викликати зовнішній сервіс, тому
офлайн-сценарій відсутній (`app/services/classifier_client.py`). Рішення
переносить обов'язковий demo-шлях на детермінований локальний sample provider,
не додаючи нових сервісів або SDK.

## Фрагмент релізу (що входить у demo)

- За замовчуванням використовується provider `local-sample`.
- Запуск без `CLASSIFIER_PROVIDER` і без `CLASSIFIER_API_TOKEN` є штатним;
  зовнішній API token не є обов'язковою передумовою demo.
- Sample provider локально класифікує текст «хочу оформити повернення» як
  `refund` і щоразу повертає той самий результат.
- Demo показує лише класифікацію та передачу результату на ручний перегляд;
  платіжні та операційні дії не входять до цього slice.
- Зовнішній provider може бути майбутнім явно керованим режимом, але не є
  частиною стандартного acceptance path.

## Заборонена зона (що demo принципово НЕ робить)

- У demo заборонено викликати живий зовнішній платний API — навіть якщо такий
  режим буде задано окремою конфігурацією.
- Demo не виконує автоматичний `refund`, якщо сума перевищує визначений поріг
  **100 у. о.** (`refund_amount > 100`). Таке звернення тільки позначається як
  `refund` і передається людині на перевірку.
- Demo взагалі не проводить платіж, не змінює замовлення і не підтверджує
  повернення коштів. Класифікація є підказкою, а не дозволом на фінансову дію.
- У slice не входять нові сервіси, SDK, production-інтеграції, фонові повторні
  спроби або функції поза описаним локальним сценарієм.

## Резервний варіант

Стандартний demo-шлях не залежить від зовнішнього сервісу: якщо зовнішня
система недоступна, `local-sample` продовжує працювати локально і дає той самий
результат. Якщо зовнішній provider явно ввімкнено в майбутньому, але він
недоступний, система не робить повторних платних викликів і повертає безпечний
результат `unknown` для ручного перегляду.

Якщо класифікація невпевнена (результат не досягає погодженого рівня впевненості
0,80), система не вгадує тему і не запускає автоматичну маршрутизацію чи
refund: вона повертає `unknown` і залишає звернення для ручного рішення. Таким
чином, відсутність сервісу або невпевненість не змінюють відтворюваний offline
результат demo і не створюють фінансової дії.

## Критерії приймання demo-slice

1. У чистому оточенні, де `CLASSIFIER_PROVIDER` і
   `CLASSIFIER_API_TOKEN` відсутні, отримання settings завершується успішно та
   має `classifier_provider == "local-sample"`.
2. У тому самому оточенні `classifier_api_token` залишається `None`; demo не
   вимагає зовнішнього token і не виконує мережевих викликів.
3. `ClassifierClient` у default-конфігурації класифікує текст
   `"хочу оформити повернення"` як `"refund"`.
4. Повторний локальний запуск із тим самим sample-текстом дає той самий
   результат без живого платного API, квоти або платіжних даних.
5. Для `refund_amount > 100` у. о. не виконується автоматичне повернення;
   результат передається на ручну перевірку.
6. При недоступному зовнішньому provider або confidence < 0,80 результатом є
   `unknown`/ручний перегляд, а не вигадана категорія чи refund.
7. Поведінку default provider, запуск без token і offline-класифікацію
   зафіксовано в `tests/test_settings.py`; фактичний pytest на цьому етапі не
   є умовою здачі.

## Зона впливу (без правок коду на цьому етапі)

- [`app/settings.py`](../app/settings.py) — дефолтний provider має бути
  `local-sample`, а token не повинен бути обов'язковим для demo; тут також
  визначається поведінка явної конфігурації зовнішнього provider.
- [`app/services/classifier_client.py`](../app/services/classifier_client.py)
  — клієнт має підтримувати локальну offline-класифікацію, безпечний fallback
  при недоступності сервісу та обережну обробку невпевненого результату; він не
  запускає автоматичний refund понад поріг 100 у. о.
- [`tests/test_settings.py`](../tests/test_settings.py) — acceptance-перевірки
  default provider, запуску без API token і результату `refund` для sample
  тексту.
