# User JTBD

## Target user
Оператор підтримки першої лінії, який протягом зміни обробляє вхідні тікети про повернення та статуси замовлень.

## Current workaround
Оператор вручну визначає тип запиту, шукає схожий старий тікет або потрібний фрагмент в окремому текстовому файлі, копіює шаблон відповіді та виправляє суму й номер замовлення. Для дорогого повернення оператор окремо звертається до провідного оператора в месенджері; історію клієнта доводиться перевіряти у трьох різних вкладках.

## JTBD
When надходить тікет про повернення або статус замовлення, I want to швидко отримати правильну категорію, релевантний шаблон відповіді та зведену історію клієнта, so I can закрити запит без зайвого ручного пошуку й повторного звернення клієнта.

## Desired outcome
Система попередньо класифікує тікет, підставляє дані в доречний шаблон і показує історію клієнта в одному місці. Повернення понад 100 одиниць валюти автоматично позначаються для погодження провідним оператором, а звичайні тікети оператор першої лінії може обробити самостійно.

## Success metric
Частка тікетів, закритих без повторного звернення клієнта, зростає з поточних приблизно 82% до щонайменше 90%.

## Human-in-the-loop
Провідний оператор вручну переглядає та погоджує кожне повернення на суму понад 100 одиниць валюти перед надсиланням відповіді клієнту; автоматизація лише виявляє такі випадки й передає їх на ручне рішення.
