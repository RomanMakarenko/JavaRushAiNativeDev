# TEAM_MAP — Conceptual Team Structure

## Використання `/help`

Команду `/help` було викликано під час розв'язання. У поточному середовищі курсова сесія не надає доступу до повного CLI Claude Code, тому `/help` повернула `"/help isn't available in this environment."` Це очікувано для навчального контексту — у реальному Claude Code `/help` виводить список усіх доступних команд та їхніх описів. Відсутність `/help` не впливає на документування structure, оскільки поверхня була визначена через прямий аналіз файлової системи.

## Surface

**Claude Code agent files** (`.claude/agents/*.md`).

Кожен агент — це окремий markdown-файл із YAML frontmatter, який визначає роль, обмеження інструментів і prompt. Агенти існують у Claude Code як **declarative building blocks** — вони не утворюють runtime-команду; їхній спільний запуск потребує ручного або скриптового оркестрування ззовні.

**Використані файли:**
- `claude/agents/lead.md`
- `claude/agents/api-scout.md`
- `claude/agents/test-scout.md`

## Roles

### Lead (координатор investigation)

| Аспект | Значення |
|---|---|
| **Файл** | `claude/agents/lead.md` |
| **Інструменти** | `Read`, `Grep`, `Glob` |
| **Мандат** | Веде shared task list investigation, розподіляє запитання між scout-агентами, збирає isolated findings у єдине зведення |
| **Обмеження** | Не mergeить зміни, не ухвалює фінального рішення |

### Teammate: api-scout

| Аспект | Значення |
|---|---|
| **Файл** | `claude/agents/api-scout.md` |
| **Інструменти** | `Read`, `Grep`, `Glob` |
| **Мандат** | Read-only розвідка backend API: читає контролери та сервіси refund flow, знаходить місце формування порядку refund-запитів |
| **Обмеження** | Read-only investigation, не редагує код, не пропонує merge |

### Teammate: test-scout

| Аспект | Значення |
|---|---|
| **Файл** | `claude/agents/test-scout.md` |
| **Інструменти** | `Read`, `Grep`, `Glob` |
| **Мандат** | Read-only розвідка тестового покриття refund flow: знаходить наявні тести навколо порядку refund-запитів, відзначає прогалини в покритті |
| **Обмеження** | Read-only investigation, не пише нових тестів, не править код |

## ⚠️ Обмеження: dedicated team feature у Claude Code відсутня

На момент написання (липень 2026) Claude Code **не має вбудованої функції «команда»** — немає:

- рантайму, який автоматично запускає кількох агентів у спільній сесії;
- вбудованого shared task list між агентами;
- agent-to-agent messaging або спільного контексту;
- деплоймент-пайплайну для командної роботи.

Файли `.claude/agents/*.md` є **building blocks**: вони декларують ролі та обмеження, але їхнє оркестрування (розподіл задач, збір результатів, human review) виконується **вручну** — людиною або за допомогою зовнішніх інструментів (shell-скрипти, make, CI).

У цьому investigation ролі `api-scout` та `test-scout` виконуються послідовно або паралельно шляхом явного завантаження кожного агента через механізм `/agent` у Claude Code. Координацію веде людина (або за потреби `lead.md`, який використовується як промпт для сесії).

## Human checkpoint

**Обов’язковий.** Lead збирає isolated findings від кожного scout-агента, формує підсумок investigation і передає його **людині для фінального review**.

Жоден агент не має права:
- mergeити зміни;
- ухвалювати рішення про подальші дії;
- стверджувати, що investigation завершено без людського підтвердження.

*Це відповідає мандату, прописаному в `lead.md`: «Human checkpoint залишається обов’язковим: підсумок investigation завжди йде на review людині.»*
