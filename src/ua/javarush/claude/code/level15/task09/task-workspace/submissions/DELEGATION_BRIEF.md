# DELEGATION_BRIEF — REFUND-204

## Scope

Виправити подвійне списання при повторному `refund` для одного `chargeId`.

Дозволені файли (allowed-paths):
- `src/api/orders/RefundService.java`
- `src/api/orders/RefundRepository.java`

Інші файли в межах проєкту не змінювати.

## Preserve

- Сигнатура методу `refund(chargeId, amount)` — тип повернення та параметри не змінюються.
- Існуюча логіка успішного першого рефанду (сума, статус) працює як і раніше.
- Код у стилі Java, що відповідає наявним конвенціям проєкту.

## Don't touch

Заборонені файли (forbidden-paths):
- `src/web/checkout/**` — UI/фронтенд не чіпаємо.
- `src/api/orders/dto/RefundRequest.java` — DTO не змінюємо.
- `config/**` — конфігурацію не чіпаємо.

Жоден інший файл поза allowed-paths не змінюється. inputs/ і решту product code не чіпаємо.

## Stop condition

Обидва критерії мають бути виконані:
1. Перший виклик `refund(chargeId, amount)` створює рефанд і повертає успішний результат.
2. Другий виклик з тим самим `chargeId` (до або після завершення першого) **не створює другий рефанд** — або повертає результат першого, або відхиляє запит як дублікат.

Поведінка має бути безпечною для конкурентних запитів (race condition при двох одночасних викликах).

## Return

- Змінені файли `RefundService.java` та/або `RefundRepository.java` з необхідними правками.
- Повідомлення про виконане завдання з описом реалізованого механізму захисту від дублікатів.
