# REFUND-204: подвійне списання при повторному refund

## Проблема
Якщо оператор натискає refund двічі поспіль (наприклад, при завислій відповіді),
створюються два рефанди на один і той самий `chargeId`. Клієнту повертається сума
двічі, бюджет іде в мінус.

## Де відтворюється
- `src/api/orders/RefundService.java` — метод `refund(chargeId, amount)` не
  перевіряє, чи вже було створено рефанд для цього `chargeId`.

## Бажана поведінка
Повторний refund для того самого `chargeId` не створює другий рефанд: або повертається
результат першого, або запит відхиляється як дублікат.

## Межі
Це backend-завдання. Кнопку UI та тексти статусів у цьому issue не чіпаємо — ними
займеться frontend-owner окремо.
