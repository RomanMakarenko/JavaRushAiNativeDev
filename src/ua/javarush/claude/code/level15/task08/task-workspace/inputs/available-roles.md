# Доступні реалізації ролей

Реалізація ролі обирається за ризиком і складністю, а не з любові до симетрії
«одна роль = один агент».

| Рівень реалізації | Коли доречно |
|---|---|
| `plan mode` | продумування меж і плану без запису в код |
| `subagent` | вузька реалізація зміни з обмеженими правами |
| `fresh session` | незалежний погляд без багажу контексту виконавця |
| `human` | дорога, чутлива або неоднозначна перевірка |

Нагадування: `security reviewer`, `performance reviewer`, `test reviewer` — це
не окремі orchestration patterns, а спеціалізації ролі `reviewer`.
