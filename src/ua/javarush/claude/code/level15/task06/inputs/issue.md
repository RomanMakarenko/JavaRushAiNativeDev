# RF-302 — неправильний порядок refund-запитів у inbox

## Контекст

У Commerce OS в inbox операторів refund-запити виводяться в неправильному порядку:
старі запити опиняються нижче за нові, і частина з них зникає з поля зору.

## Що запропонували

Команда запропонувала зібрати conceptual agent team (`lead` + scout-ролі) і доручити
йому розібратися з issue. У тексті пропозиції, крім розумного read-only investigation,
проскочили надто широкі обіцянки: ніби team сама виконає merge, обійдеться без
review і доставить фікс у production автономно.

## Чому це важливо для валідатора

Клас `TeamPromiseValidator` має відсікати такі обіцянки на корені. Для conceptual
team допустима лише `READ_ONLY_INVESTIGATION`, а `AUTO_MERGE`, `NO_REVIEW` і
`AUTONOMOUS_PRODUCTION` мають вважатися забороненими.
