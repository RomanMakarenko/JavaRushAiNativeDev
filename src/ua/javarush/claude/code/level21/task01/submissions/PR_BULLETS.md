## Summary
- `RefundService.calculateRefund` отримав новий параметр `boolean expedited` — для прискореного повернення з суми утримується сервісний збір 5% (цілочисельна арифметика `refund - (refund * 5 / 100)`).
- `RefundController.refund` оновлено відповідно — тепер передає `request.expedited()` у сервіс.

## Risks
- **Breaking change публічного API:** сигнатуру `calculateRefund(int, int)` замінено на `calculateRefund(int, int, boolean)` без зворотної сумісності — будь-які інші виклики (тести, інші сервіси) перестануть компілюватися. У дифі видно оновлення лише одного виклику; потрібно перевірити всіх споживачів методу.
- **Залежність від невидимої зміни в `RefundRequest`:** код покладається на метод `request.expedited()`, але сам `RefundRequest` у диф не входить — якщо поле не додане, збірка впаде.
- **Цілочисельне округлення збору:** `refund * 5 / 100` заокруглює вниз; для малих сум (наприклад, `refund < 20`) збір дорівнює 0, тобто клієнт фактично не платить 5%. Правила округлення не визначені в коді.
- **Потенційне переповнення:** `refund * 5` може переповнити `int` для дуже великих сум (понад ~429 млн), даючи некоректний результат.
- **Застосування збору після віднімання бонусів:** збір 5% нараховується на суму вже після вирахування `usedCredits`, а не на повну сплачену суму — якщо бізнес-вимога інша, результат буде хибним.
- **Відсутні тести:** у дифі немає оновлених/нових тестів на граничні значення (нульове повернення, малі суми, суми кратні 20 тощо).
- **Магічне число 5%:** відсоток захардкоджений у тілі методу; варто винести у константу/конфіг для подальшої зміни.
