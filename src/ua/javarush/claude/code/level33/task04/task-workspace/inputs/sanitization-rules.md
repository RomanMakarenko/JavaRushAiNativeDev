# Правила санітизації для публічного proof-of-work

- Не виносити raw secrets і токени.
- Не виносити private/internal URL (наприклад `*.local`, staging, admin-панелі).
- Не використовувати confidential-мітки та внутрішні назви команд.
- Не вигадувати метрики, користувачів і production-claims без підтвердження.
- Кожен запис зобов’язаний містити секції: Problem, What I owned, AI role, Verification, Result, Links, Limitations.
- Брати обмежену кількість сильних записів із різних domains, а не дамп усього.
