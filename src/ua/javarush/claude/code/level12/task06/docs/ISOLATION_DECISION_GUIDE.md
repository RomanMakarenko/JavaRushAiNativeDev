# Isolation Decision Guide

Швидкий вибір режиму ізоляції (`worktree`, контекст, комбінація або відсутність).

---

## Context only
**Ізольований контекст, спільний filesystem.**

Захищає **reasoning основної сесії**: агент отримує власне
уявлення про стан проєкту, не засмічуючи основний чат
проміжними міркуваннями. Усі зміни йдуть на спільну гілку.
Зручно для рефакторингу й невеликих змін, які не блокують
інших.

> **Приклад:** агент перейменовує методи в сервісному класі.
> Зміни торкаються одного файлу, конфлікти з паралельними
> агентами малоймовірні. Контекст оновлюється з гілки,
> але worktree не потрібен.

---

## Worktree only
**Спільний контекст, ізольований filesystem.**

Захищає **файли та Git state**: кілька агентів одночасно
змінюють файли, кожен у власній гілці й директорії, без
конфліктів. Контекст (історія чату) не клонується — агент
бачить стан гілки як є. Не замінює context isolation.

> **Приклад:** два агенти паралельно виправляють баги в різних
> модулях одного пакета. Кожен отримує власний worktree,
> читає спільний CLAUDE.md, але пише у свою гілку.

---

## Both (Context + Worktree)
**Повна ізоляція: окремий контекст і окремий filesystem.**

Кожен агент отримує власний чат і власну гілку. Найбезпечніший
режим для потенційно конфліктної паралельної роботи, але
найдорожчий за токенами й часом створення.

> **Приклад:** рев'ювери перевіряють три різні гілки фіч.
> Кожен має свій чат для обговорення знахідок і окремий
> worktree, щоб експериментувати з виправленнями без впливу
> на інших.

---

## Neither (без ізоляції)
**Спільний контекст і спільний filesystem — звичайна робота.**

Агент пише прямо в робочу гілку, зміни видно одразу.
Найпростіший і найдешевший режим. Підходить для лінійних
завдань без паралелізму.

> **Приклад:** одне завдання на одній гілці: додати endpoint
> і тест. Агент робить зміни по черзі, ніхто більше не чіпає
> ті самі файли.
