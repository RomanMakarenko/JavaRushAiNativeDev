# WORKFLOW_NOTE.md

## Зовнішній сигнал

Надійшов issue [REF-482](./inputs/issue.md) з трекера задач (пріоритет high, мітки: refunds, sorting, support-tools). В описі повідомляється, що агенти підтримки працюють зі списком повернень зверху вниз, але заявки з `manualReview=true` тонуть серед звичайних, через що їх обробка затримується. Зазначено модуль `refunds` як місце логіки сортування.

## Гіпотеза

Можливо, причина в тому, що метод `sortForSupport()` у `RefundService` сортує список лише за часом створення (`createdAt`), не враховуючи прапорець ручної перевірки. Якщо це так, то заявки з `manualReview=true` випадково опиняються внизу списку, коли вони старіші за звичайні. Гіпотезу треба перевірити зачитуванням поточного коду компаратора.

## Перевірка

1. Відкрити `RefundService.java` і знайти метод `sortForSupport()`. Подивитися, які поля бере участь у компараторі.
2. Якщо сортування лише за `createdAt` — гіпотеза підтверджена. Якщо `manualReview` уже враховано — гіпотеза спростована, шукати іншу причину.
3. Зафіксувати знайдену логіку в специфікації та описати необхідну зміну: композитний компаратор `manualReview` (true вище) + `createdAt` (новіші вище).
4. Перевірити, чи є інші місця в модулі `refunds`, де відбувається сортування списку повернень (пошук, фільтр).
5. Оцінити вплив на клієнтів `RefundView` — чи хтось покладається на поточний порядок.
