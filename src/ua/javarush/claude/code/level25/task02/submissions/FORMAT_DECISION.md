# Рішення щодо формату capstone

## Обраний формат

**AI-native MVP**

## Коротке обґрунтування

Ідея передбачає створення невеликого робочого прототипу з нуля: сервіс
приймає вивантаження підписок, перераховує MRR за прозорими правилами та
показує розбіжності з поточним розрахунком. Це новий самостійний інструмент,
а не зміна наявної кодової бази, міграційний slice чи автоматизація процесу.
Початок із чистого Spring Boot 3.x на Java 21 також відповідає підходу MVP із
мінімальною окремою кодовою базою.

## Межі проєкту

Capstone — це **окремий репозиторій студента**, створений з нуля. Він **не є
продовженням Commerce OS або CashFlow Dashboard**. Ці системи можуть бути лише
прикладами та legacy-контекстом для задачі; сам сервіс аналізу MRR розробляється
незалежно від них.
