# Scope guardrails

## Level

**Middle.** Проєкт має продемонструвати один завершений core flow з обробкою основних помилок, локальною verification і контрольованим workflow. Production-інфраструктура не є частиною цього scope.

## Format

**New small product.** Створюється невеликий локальний продукт для оператора маленької SaaS-команди — без обов'язкових зовнішніх інтеграцій.

## Core flow

**Керування життєвим циклом однієї підписки оператором:**

1. Оператор вводить ідентифікатор клієнта та параметри плану.
2. Система перевіряє обов'язкові дані й відхиляє некоректний запит.
3. Система створює підписку зі статусом `ACTIVE` і зберігає її в локальному сховищі.
4. Оператор знаходить підписку та скасовує її.
5. Система переводить підписку в `CANCELLED` і не дозволяє повторно скасувати вже скасовану підписку.

У стартовій версії це один локальний операторський сценарій для однієї інсталяції. Результат має бути demo-ready і перевірятися локально.

## Removed scope

Функції нижче свідомо не входять до першої версії й можуть бути окремими наступними slices:

- реальні платежі через Stripe або іншого платіжного провайдера;
- multi-tenant режим і підтримка кількох організацій в одній інсталяції;
- автодеплой у AWS;
- production CI/CD;
- email- та push-кампанії при зміні статусу підписки;
- аналітичний дашборд із графіками виручки;
- інтеграція з Figma для синхронізації макетів білінгу;
- автоматична обробка тікетів;
- додаткові незалежні flow, не потрібні для створення та скасування підписки;
- production deployment загалом.

## Not using now

- зовнішні API та webhook-механізми платіжного провайдера;
- розрахунки, захист і зберігання платіжних даних;
- tenant isolation, організаційні ролі та складна авторизація;
- хмарна інфраструктура AWS, infrastructure-as-code і production secrets management;
- розподілений CI/CD pipeline;
- асинхронні email/push черги, retry та delivery tracking;
- event-driven інтеграції й message broker для статусних змін;
- аналітичний pipeline, агрегації виручки та графічна візуалізація;
- Figma API/MCP або синхронізація зовнішніх артефактів;
- multi-agent orchestration;
- масштабування, high availability і production observability.

Ці обмеження захищають один перевірюваний core flow від розростання scope. Новий механізм додається лише після того, як поточний flow має тести, локальну verification і достатню evidence.
