# Три випадки зовнішнього доступу в Commerce OS

Команда працює над Commerce OS і зберігає свої робочі активи в Workflow Kit.
Зараз на столі три ситуації, і по кожній потрібно вирішити, чи виправданий MCP.

## Випадок A — одноразовий локальний stack trace

Після невдалого тесту є стек помилки з локального запуску. Проєкт відкрито
поруч, лог перед очима. Потрібно один раз розібрати причину падіння.

## Випадок B — щоденний intake завдань із issue tracker

Щодня в трекері з’являються нові issue Commerce OS (наприклад, COM-481).
Розробник копіює заголовок, опис, мітки та коментарі й просить Claude
зібрати чернетку `TASK_SPEC.md`. Це відбувається багато разів на день.

## Випадок C — автоматично закривати issue після merge

З’явилася ідея: коли PR змёржено, автоматично переводити пов’язаний issue в
статус `Done` через той самий issue tracker. Це вже write-дія, що змінює
зовнішній стан.
