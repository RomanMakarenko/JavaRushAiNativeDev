## Why MCP is external

### 2.1. Різна природа даних

**Репозиторій (код і docs)** — це *curated knowledge*:
- Версіонований — кожна зміна має історію й автора.
- Рецензований — проходить code review.
- Довгоживучий — визначає архітектуру та поведінку системи на місяці / роки.
- **Статичний зріз** — фіксує стан на момент коміту.

**MCP (Model Context Protocol)** — це *live operational surface*:
- Неверсіонований — issue трекера змінюється щохвилини.
- Не рецензується командою — алерт із моніторингу надходить автоматично.
- Короткоживучий — актуальний для поточної сесії / інциденту.
- **Динамічний потік** — відображає стан систем у реальному часі.

### 2.2. Різні цілі

| Що робить | Код / docs репозиторію | MCP / зовнішні поверхні |
|-----------|----------------------|------------------------|
| Фіксує архітектуру | ✅ | ❌ |
| Зберігає бізнес-логіку | ✅ | ❌ |
| Повідомляє про інцидент | ❌ | ✅ |
| Несе поточний баг-трекер | ❌ | ✅ |
| Проходить рев'ю | ✅ | ❌ |
| Оновлюється в реальному часі | ❌ | ✅ |

### 2.3. MCP — це міст, а не заміна

MCP **не замінює** репозиторій і не повинен цього робити, тому що:

1. **Репозиторій — authoritative source.** Якщо код і MCP-поверхня суперечать одне одному, правда на боці коду. MCP — це операційний контекст, а не специфікація.

2. **MCP не має гарантій узгодженості.** Трекер може показувати застарілий статус задачі; моніторинг може давати хибний алерт. Репозиторій же завжди відтворюваний — `git checkout` дає той самий стан.

3. **MCP — тимчасовий.** Зовнішні дані актуальні в межах сесії або розслідування. Код живе роками. Змішувати їх — означає втратити референсну точку.

4. **Безпека та контроль доступу.** Код репозиторію контролюється командою через PR і рев'ю. MCP підключає зовнішні системи, до яких команда може не мати адміністративного контролю. Тримати їх окремо — це принцип найменших привілеїв для контексту.

### 2.4. Висновок

**MCP розширює контекст назовні, а не дублює контекст усередину.**

Код і документи репозиторію — це *фундамент*: вони визначають, як система повинна працювати.
MCP-поверхні — це *оболонка*: вони показують, як система працює насправді, з якими проблемами стикається і що потребує змін.

Розділення внутрішнього (codebase) і зовнішнього (MCP) контексту дає змогу:
- Завжди мати чисту референсну модель системи.
- Отримувати операційний контекст, не засмічуючи репозиторій.
- Ухвалювати рішення на основі двох джерел, розуміючи природу кожного.
