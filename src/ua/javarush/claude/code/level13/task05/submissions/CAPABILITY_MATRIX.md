# Матриця можливостей MCP-серверів

## Легенда

| Позначка | Значення |
|----------|----------|
| ✅       | Інструмент доступний |
| ❌       | Інструмент відсутній |
| 👁️      | Read-only операція |
| ✏️       | Write операція |

---

## 📖 Документація (Docs Lookup)

**Сервер:** `docs-lookup` · режим: `read-only`  
**Файл-джерело:** `manifests/docs-lookup.md`

| Інструмент | Тип | Призначення |
|------------|-----|-------------|
| `search_docs` | 👁️ read-only | Пошук в офіційній технічній документації |
| `get_doc_page` | 👁️ read-only | Отримання конкретної сторінки документації |

**Варіанти використання (лише читання):**
- Пошук API-референсів, синтаксису, сигнатур методів
- Вичитування сторінок документації прямо з робочої сесії

**Варіанти використання (із записом):** ❌ _Сервер суто read-only, операції запису відсутні._

---

## 🎫 Трекінг завдань (Issue Tracker)

**Сервер:** `issue-tracker` · режим: `read-write`  
**Файл-джерело:** `manifests/issue-tracker.md`

| Інструмент | Тип | Призначення |
|------------|-----|-------------|
| `get_issue` | 👁️ read-only | Отримання картки issue за ключем |
| `list_issues` | 👁️ read-only | Список issue за фільтром |
| `create_issue` | ✏️ write | Створення нової картки |
| `update_issue` | ✏️ write | Зміна полів існуючої картки |

**Варіанти використання (лише читання):**
- Перегляд картки issue за ключем
- Фільтрація та перелік issues за статусом, виконавцем, пріоритетом

**Варіанти використання (із записом):**
- Створення нової картки прямо із сесії (intake вхідних issues)
- Оновлення статусу, пріоритету, виконавця існуючої картки

---

## 📊 Моніторинг (Monitoring)

**Сервер:** `monitoring` · режим: `read-write`  
**Файл-джерело:** `manifests/monitoring.md`

| Інструмент | Тип | Призначення |
|------------|-----|-------------|
| `get_metric` | 👁️ read-only | Отримання значення метрики |
| `list_alerts` | 👁️ read-only | Список активних алертів |
| `ack_alert` | ✏️ write | Підтвердження (acknowledge) інциденту |

**Варіанти використання (лише читання):**
- Запит поточних метрик (CPU, пам'ять, RPS, тощо)
- Перелік активних алертів — хто, коли, який поріг порушено

**Варіанти використання (із записом):**
- Підтвердження алерта (acknowledge) — позначення, що інцидент узятий у роботу
- _(Створення або вимкнення алертів не передбачено)_

---

## 🔄 Контроль версій / PR (Source Control)

**Сервер:** `pr-review` · режим: `read-write`  
**Файл-джерело:** `manifests/pr-review.md`

| Інструмент | Тип | Призначення |
|------------|-----|-------------|
| `get_pull_request` | 👁️ read-only | Метадані PR |
| `get_diff` | 👁️ read-only | Diff змін PR |
| `post_comment` | ✏️ write | Залишити коментар у PR |
| `merge_pull_request` | ✏️ write | Виконати merge PR |

**Варіанти використання (лише читання):**
- Перегляд метаданих pull request (автор, статус, гілки, рев'юери)
- Читання diff змін для code review

**Варіанти використання (із записом):**
- Публікація review-коментаря прямо з сесії
- Merge pull request після схвалення (без ручного переходу в GitHub)
