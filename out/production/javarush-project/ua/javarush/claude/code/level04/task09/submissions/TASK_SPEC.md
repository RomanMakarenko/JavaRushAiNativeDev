# Task Spec — Checkout Flow: Promocode Double-Apply Fix

## Goal

Виправити помилку подвійного застосування промокоду в checkout flow модуля `commerce-checkout`, коли користувач натискає кнопку «Застосувати» повторно до отримання відповіді сервера. Підсумкова сума замовлення не має зменшуватися більше ніж на величину однієї знижки.

## Scope

**Включено:**
- Захист від повторного застосування промокоду на серверному рівні (перевірка перед застосуванням знижки).
- Захист від повторного застосування промокоду на рівні UI (блокування кнопки після першого натискання до відповіді сервера).
- Додаткове поле до схеми даних кошика, яке фіксує, чи промокод уже застосовано.
- Відображення результату: повідомлення про успіх (текст + перекреслена стара сума) або popup з помилкою.
- Unit-тест, інтеграційний тест, E2E-тест.

**Виключено:**
- Зміна схеми бази даних знижок або промокодів.
- Зміна логіки розрахунку знижки (лише захист від повторного застосування).
- Зміни, не пов'язані з checkout flow.

## Constraints

- Схема бази даних не змінюється (крім додаткового поля статусу в кошику).
- Поріг і тип знижки надходять із конфігурації (не змінювати).
- Існуючі тести мають проходити після виправлення.
- Повідомлення про успіх: текст «Знижка X% застосована», перекреслена стара сума, оновлена сума поряд.
- Повідомлення про помилку (недійсний / прострочений / вичерпано ліміт): спливаюче вікно (popup).

## Evidence

**Спостережувана поведінка:**
- Під час оформлення замовлення промокод зі знижкою застосовується двічі, якщо користувач натискає кнопку «Застосувати» повторно до відповіді сервера.
- Підсумкова сума замовлення зменшується на подвійну величину знижки.
- Логи показують два послідовні виклики `applyPromoCode` з одним і тим самим кодом.

**Джерела:**
- [Raw Request](../inputs/raw-request.md) — початковий запит
- [Evidence Summary](../inputs/evidence-summary.md) — опис багу
- [Interview Notes](./INTERVIEW_NOTES.md) — уточнення замовника

**Відтворюється в:** checkout flow модуля `commerce-checkout`.

## Acceptance criteria

1. **Серверний захист:** при повторному виклику `applyPromoCode` з тим самим кодом для одного кошика знижка не застосовується вдруге; сервер повертає відповідний статус (помилка або ідемпотентний успіх).
2. **UI-захист:** кнопка «Застосувати» блокується після першого натискання до отримання відповіді сервера.
3. **Схема даних:** у кошику є поле, яке фіксує, чи промокод уже застосовано; серверна перевірка використовує це поле.
4. **Успішне застосування:** користувач бачить текст «Знижка X% застосована», перекреслену стару суму, оновлену суму поряд.
5. **Помилка:** при недійсному / простроченому / вичерпаному промокоді з'являється popup з повідомленням про помилку.

## Verification plan

| Рівень | Що перевіряє | Інструмент |
|---|---|---|
| Unit-тест | Серверна логіка перевірки повторного застосування промокоду | JUnit / відповідний фреймворк |
| Інтеграційний тест | Взаємодія UI та сервера в checkout-потоці | Spring Boot Test / відповідний фреймворк |
| E2E-тест | Симуляція подвійного натискання кнопки; перевірка, що знижка застосовується лише один раз | Selenium / Playwright / відповідний фреймворк |

**Додатково:** запустити всі існуючі тести — вони мають проходити без помилок.
