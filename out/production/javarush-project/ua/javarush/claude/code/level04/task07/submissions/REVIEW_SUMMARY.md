# Review Summary — WEB-208 (newsletter preferences)

## Scope

**Факт із diff:** У `NewsletterForm.tsx` рядок `onSubmit({ email, frequency: "weekly" })` змінено на `onSubmit({ email, frequency })` — тепер у payload потрапляє значення зі стану компонента, а не захардкожене `"weekly"`. Тест у `NewsletterForm.test.tsx` оновлено: очікувана `frequency` змінено з `"weekly"` на `"daily"`, що відповідає вибраному користувачем значенню.

**Збіг з expected-scope.md:** ✅ Зміни повністю відповідають очікуваному обсягу:

- **Allowed** — передавати вибрану частоту в payload: виконано
- **Allowed** — оновити тест: виконано
- **Out of scope (не змінено):** стилі, API endpoint, рефакторинг, нові пакети — не зачеплено

Задіяні файли: `src/components/NewsletterForm.tsx` та `src/components/NewsletterForm.test.tsx` — збігається з очікуваними.

## Risks

- **Низький ризик регресії** — зміна торкається лише одного рядка логіки: значення `frequency` у payload. Тип `Frequency` (`"daily" | "weekly"`) залишився без змін, інтерфейс `NewsletterPayload` не змінювався.
- **Тест оновлено** — перевіряє, що після вибору "daily" саме це значення надсилається. Тест проходитиме тільки з новою логікою.
- **Потенційний ризик:** якщо бекенд раніше покладався на те, що `frequency` завжди `"weekly"`, це може вплинути на серверну обробку. Однак це не входить у scope frontend-компонента.

## Decision

**APPROVE** — зміни точно відповідають очікуваному обсягу, ризики мінімальні, тест оновлено.

## Next steps

1. Перевірити, чи готовий бекенд отримувати `"daily"` замість гарантованого `"weekly"`.
2. Прогнати тести перед мержем.
3. Якщо бекенд готовий — прийняти PR.
